## 方法概览

从 GR、PE、SP、CAL、AC、DEN、CNL、RXO、RT 九条曲线构造固定 206 维特征。两个多尺度一维 U-Net 分别读取完整特征和 68 维精简特征；精简分支使用井内相对特征，对 31 条数值特征进行逐点尺度与偏移校正。

骨干结合局部点注意力和全局 patch 余弦注意力。每个输入窗口 256 个深度点，监督与输出中心 128 点。每个目标预测默认状态概率与连续混合分布，最后按官方容差评分的期望收益选取预测值。五折推理等权融合完整后验，不能先解码再平均数值。

训练使用默认状态 BCE 与非默认连续 NLL，辅助监督逐步退场。覆盖所有训练点的全局表对持续冲突的疑似坏样本降低最终损失权重，保留恢复机制；单凭损失大不把困难样本判为异常。方法不使用树预测、预训练权重、伪标签、测试标签或事后拟合的 OOF 融合。

## 训练流程：先第五折，再完整五折

1. **先集中优化固定第五折。** 按井固定 GroupKFold 划分，每折 64 口井训练、16 口井验证；新思路先只训练第五折，比较网络、特征或损失改动的收益，不换折挑分数。后期实验上限 80 轮、patience=18，每轮计算验证分数，最终直接恢复最佳 checkpoint，不按最佳轮次数重新训练。
2. **第五折有收益且达到当时门槛后，补齐另外四折。** 保持同一方法、配置和划分，复用已有第五折结果，在其余四折分别从头训练并选各自最佳 checkpoint。当前门槛为第五折严格超过 80.4，并不要求其余每一折都超过该门槛。
3. **汇总完整 OOF，判断最终收益。** 每口井只采用未用该井训练的对应折模型预测，拼接全部验证行后计算官方总分。单折提升不等于完整五折提升；未过筛选门槛的方案保留单折结论，不报告虚构的完整 OOF。

### 当前交付结果来自哪里

交付的 `81.713233` 来自 **双骨干 + 精简视图逐点特征校准**，对应实验 `pure_dl_paired_calibrated_view_sequence`。它先在第五折得到 **80.200358**，超过当时的严格 `>80.2` 门槛，然后保持冻结的 **75 轮上限 / patience=18** 配置补齐其余四折，得到下表的完整 OOF。之后提高到 `>80.4` 的门槛不追溯改变该历史实验。

实际提交的 `result.json` 则来自这套方法的**五折最佳模型共同推理**：先在每折内融合两个骨干的完整后验，再对五折的期望官方效用等权平均后解码，输出 10 口测试井的 95,948 行预测。交付不是只用第五折，也不是使用最后一次路由实验的权重；后续路由实验尚未补齐五折。

## 最新进展：最后一次后验信息路由实验

最后一次训练为 `pure_dl_paired_posterior_router80_sequence`。在已有双骨干输入路由上，除当前点的 68 维输入特征，再加入两个骨干、三个目标的 **24 维后验描述量**：默认状态概率、分量权重熵、条件均值和条件总标准差。路由器根据这些信息学习各目标对两个骨干的融合权重，而不是预设“越自信权重越大”。

后验描述量和用于路由损失的骨干输出均断开梯度；骨干仍用各自的原预测损失训练，路由器使用独立优化器。共享降权表的后续更新仍可能间接影响骨干，不能称为完全独立的训练轨迹。该实验未叠加局部上下文路由的卷积。

## 推理

本分支**不上传原始数据、模型权重、逐行标签/预测或提交 ZIP**。先把另行取得的五个 `fold_1.pt` 至 `fold_5.pt` 放入 `package_dl/models/`，再执行：

```bash
python -m pip install -r package_dl/requirements.txt
python package_dl/predict.py --data_dir /path/to/data --output /path/to/result.json --device cuda
```

输入可以是包含 `test/` 的数据根目录，或直接包含井 TXT 的目录。输出为严格的 `resultData → logId/predictions → DEPTH/POR/PERM/SW` JSON，并生成只含根目录 `result.json` 的 `result.zip`。没有模型文件时不能仅凭 Git 克隆执行推理。

已交付版本在 Windows、normal 环境的 GPU PyTorch 上从新解压目录运行两次：10 口井、95,948 行，JSON 字节完全一致，峰值显存约 401 MiB。仅核验运行、结构与数值范围，不说明测试精度；Linux 与本版本 CPU 推理未实测。
