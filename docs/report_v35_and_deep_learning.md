## 4. v3.5 的高优先级风险

### 4.1 已实测：128 行异常标签被纳入训练

[src/data.py:61–65](../experiments/v3.5/source/src/data.py#L61-L65) 用 `has = v > MISSING / 2`，其中 `MISSING=-99999`。因此 `-9999`、约 `-2000`、约 `-6000` 都会被认作有效且非默认标签。

直接读取本地 80 口井、730,268 行得到：

| 目标 | 原 v3 物理范围内标签数 | v3.5 `has` 标签数 | 被误收的负异常值 |
| --- | ---: | ---: | --- |
| POR | 723,567 | 723,695 | `-9999` ×126、`-2001.673` ×1、`-6000.336` ×1 |
| PERM | 723,557 | 723,685 | `-9999` ×126、`-2001.745` ×1、`-6000.373` ×1 |
| SW | 723,557 | 723,685 | `-9999` ×126、`-1921.853` ×1、`-5960.427` ×1 |

三目标同时有效行从原 v3 的 **723,556** 变为 v3.5 策略下的 **723,684**。这些值参与分箱、门控和状态标签构建；不能把它们当作可学习地质信号。原 v3 [package/src/data.py:14–43](../package/src/data.py#L14-L43) 的物理范围过滤会置为缺失。

修复方向：使用一致的目标物理范围和有效掩码，保留按目标缺失与三目标联合有效的显式区别；禁止把异常值简单裁剪成合法标签。**修复必须另立实验版本，不能改本次提交归档后仍沿用其分数。**

### 4.2 源码确认：NN 混用每折分箱边界

1. [train_trees.py:109–117](../experiments/v3.5/source/train_trees.py#L109-L117) 为每个折 `k` 用 `fold != k` 的训练标签拟合 `bins[k]`。
2. [train_nn.py:81–100](../experiments/v3.5/source/train_nn.py#L81-L100) 在外层训练开始前，按每口井**自己的折号**选择边界，构建该井分箱标签。
3. [train_nn.py:196–220](../experiments/v3.5/source/train_nn.py#L196-L220) 训练外折 `k` 时混合来自其他多个折的井，却仍沿用上述多套标签边界。

结果是一个 NN 分类头的同一 class ID 对不同井代表不同数值区间；其他折边界的拟合集合还可能包含外层验证折标签。代码注释中的“无泄漏”不能描述这个控制流。原 [src/nn_seq.py:294–310](../src/nn_seq.py#L294-L310) 则每个外折先建立统一训练分箱，再用于该折训练和验证。

正确方向：进入外折 `k` 后，仅从它的训练井建立一套边界，为该外折所有训练/验证井分箱；保存模型对应的边界、中心、列顺序和归一化统计。

### 4.3 源码确认：推理将平均概率与各折支持错配

[predict.py:144–163](../experiments/v3.5/source/predict.py#L144-L163) 先对所有 NN 折/种子平均分箱概率，再把相同平均概率分别配给各折中心。一般情况下：

\[
\frac1F\sum_f p_f K_f^\top
\ne
\left(\frac1F\sum_f p_f\right)
\left(\frac1F\sum_f K_f\right)^\top.
\]

除非支持矩阵相同或出现特殊抵消，否则两者不等价。应先对同折种子平均，保持 `p_f` 与本折 `K_f` 配对，再在**公共动作网格**上平均期望效用，最后一次 argmax。不要按分箱列索引跨不同支持直接平均。树侧已有按折效用聚合，不能把整个 v3.5 误写为“平均已解码值”。

### 4.4 线下验证口径须降级表述

- v3.5 的中位数、NN 全局统计与 base 特征方差选择在折外统一拟合，见 [train_nn.py:162–186](../experiments/v3.5/source/train_nn.py#L162-L186)。这是使用验证井**输入统计**，与 §4.2 的标签边界泄漏不同，但不是严格训练折独立预处理。
- v3.5 按所有原始行数做 `GroupKFold`；v3 按完整有效标签行做分组。即使都叫 5 折，也不能在没有保存井号/深度/折号前假定分配相同。
- v3 与 v3.5 的 assembly“嵌套”都主要指**固定 OOF 上的决策选择交叉拟合**：权重/阈值不直接使用当前外折的评分标签，但其他折 OOF 的基础模型可能训练过当前外折。它不是严格外层内重新训练基础模型的 nested CV。
- 单源 OOF 上选最优阈值后原样回评、全 OOF 最佳 `global_acc` 属选择后分数；不可与 `nested_acc` 混为一谈，更不可等同盲井成绩。

本文保留历史报告中的数字与名称，不回写旧实验；新研究应明确这种局限，而非继续使用“完全无泄漏/无偏”的强结论。

## 5. 队友方案做了什么

本节以固定提交的 [METHOD.md](https://github.com/whiteicey/welllog-reservoir-hybrid/blob/f07a7d7d3be341477d9ef7624510e73eb0168d0e/docs/deep_learning/METHOD.md) 和 [EXPERIMENTS.md](https://github.com/whiteicey/welllog-reservoir-hybrid/blob/f07a7d7d3be341477d9ef7624510e73eb0168d0e/docs/deep_learning/EXPERIMENTS.md) 为说明，以对应源码和保存的 JSON 为证据。

### 5.1 校准双骨干，而非纯原始曲线端到端

- 9 条曲线生成 **206 维工程特征**；排除 DEVI/AZIM/BIT/CASE，保留相对深度，不用绝对深度分支。它“纯 DL”指没有树模型，不代表没有特征工程。
- 每折两个独立 global-cosine U-Net 成员，通道 64/96/128/192，局部 dot-product attention 与窗口内 patch-token cosine attention。
- 输入窗口 256 点，中心 128 点监督/输出；“global”作用于当前窗口的 patch 汇总 token，**不是整批多井 attention，也不是直接整井全局 self-attention**。
- 一个成员用全 206 维；另一个仅保留 41 维瞬时视图 + 27 维井内相对视图（其他标准化列置零）。
- 第二成员用 `27→32→62` 的条件 MLP，**仅将末层权重与偏置零初始化**，使初始变换为恒等；对 31 个数值列做逐点条件仿射校准：`x' = x × (1+tanh(gamma)) + tanh(beta)`。首层保留默认初始化，条件来自井内 rank/ZIQR/QNORM，不来自测试标签。

源码：[paired_calibrated_view_sequence.py](https://github.com/whiteicey/welllog-reservoir-hybrid/blob/f07a7d7d3be341477d9ef7624510e73eb0168d0e/experiments/pure_dl/paired_calibrated_view_sequence.py#L9-L49)。这些井内统计家族在原 v3 已有，新增点是**作为特定成员的逐点校准条件**，不是首次发明井内统计。

### 5.2 连续密度、默认原子与效用决策统一

每个目标预测默认概率及 8 分量连续分布。POR / PERM / SW 分别在 log1p / log10 / ln 空间建模；POR 用 Student-t(df=3)，PERM/SW 用 Normal。损失包含默认 BCE、非默认连续 NLL，以及随轮次衰减的中/粗尺度辅助监督。

两成员固定等权融合**完整后验**，默认概率为 `p=(p0+p1)/2`；连续条件部分的成员权重为：

\[
\widetilde\pi_m = \frac{\pi_m(1-p_m)}{\sum_j \pi_j(1-p_j)}.
\]

因此不是给拼接后的 16 个条件分量一律相同权重。默认值也是候选动作；每折将密度映射到训练支持网格，五折平均官方核期望效用后再决策。没有 OOF 拟合融合权重、后处理温度或学习式 router。

源码：[paired_backbone_sequence.py:9–23](https://github.com/whiteicey/welllog-reservoir-hybrid/blob/f07a7d7d3be341477d9ef7624510e73eb0168d0e/experiments/pure_dl/paired_backbone_sequence.py#L9-L23)、[package_dl/predict.py](https://github.com/whiteicey/welllog-reservoir-hybrid/blob/f07a7d7d3be341477d9ef7624510e73eb0168d0e/package_dl/predict.py)。

### 5.3 Q 权重与验证限制

Q 仅在训练点上，用持续高 NLL、窄分布、极端尾概率与稳定性等共同判断条件冲突，再降低/恢复点权重。**这不是确定的坏标签检测，也不应取代明确的异常值清洗。** 错误降权可能损害薄层与稀有储层；目前未见完全同折、同预算、同种子的 Q/no-Q 单因素证据。

完整交付采用历史 75 轮、patience 18 的配置；每折使用自身验证 TOTAL 最优 checkpoint。架构先多次复用第五折筛选后才补齐其余折。因此它有按井留出预测，但不是从未参与选择的独立外层测试。80 轮 router 系列另有学习率周期，不能当作原 75 轮方案仅多跑 5 轮。

原分支保存两次独立 CUDA CLI 推理、相同测试结果字节的记录；本次只复制证据 JSON，没有重跑。代码仓库不含该交付的五折权重或结果 ZIP；文档中的 `D:/match_predict/submission_calibrated_pair/` 在本机不存在。不能宣称“clone 后即可复现该分数”。

## 6. 怎样理解相对优势

### 6.1 保存的逐目标 OOF 提供方向，不证明融合增益

下表将目标准确率统一乘以 100；**仅为已有报告的并列比较，不是同流程新消融**。

| 指标 | v3 assembly D | 队友校准双骨干 | 差值（百分点） |
| --- | ---: | ---: | ---: |
| POR | 78.9300 | 79.2155 | +0.2855 |
| PERM | 90.3386 | 90.4850 | +0.1465 |
| SW | 75.2425 | 75.0824 | −0.1601 |
| 综合 | 81.6324 | 81.7132 | +0.0809 |

这支持“优先检查 POR/PERM 的神经密度、保留原 SW 优势”的研究方向，但**不能拿每目标较高分拼出可宣称的最优融合**：来源需要逐行对齐、选择需要嵌套或独立留井验证，逐井误差相关性尚未计算。v3.5 无 OOF，不参与该线下表。

队友从单成员 global-cosine 完整 OOF 81.5027 到校准双成员 81.7132，记录增益 +0.2105。第五折路径是 79.989867 → 80.008041（双同视图）→ 80.088515（瞬时视图）→ 80.143443（加井内视图）→ 80.200358（逐点校准）。这是单种子开发轨迹，不是严格多种子因果消融。

### 6.2 应修正旧 ROADMAP 的泛化判断

原 v3 的“纯序列替代树模型 −3.2”只描述当时的特定 WellNet/TCN 试验；“纯曲线路线已试尽”“井级自适应整体无效”不应推广为结构上不可能。

新分支至少表明，带工程特征、校准、多分量密度、窗口 attention 的 DL 路线能达到与树–序列混合接近的完整 OOF。它不推翻 v3 的已测负结果，但足以要求重开更具体的假设。**缩小负结果的适用范围，比恢复一个旧比较文档或一键合并整个分支更合理。**
