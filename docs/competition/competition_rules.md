## 一、赛题详情

### 1.1 业务背景

油气勘探开发过程中，孔隙度（POR）、渗透率（PERM）、含水饱和度（SW）等储层参数是储层品质评价、油气储量计算和开发方案制定的核心参数，广泛应用于资源评价、储量计算、开发部署和动态调整等关键业务环节。测井技术通过在钻孔中连续采集地层的电学、声学、放射性等多种物理响应信息，形成高分辨率测井曲线，为储层参数的定量评价提供了核心数据支撑。基于测井数据准确获取储层参数，是实现油气勘探开发精细化、智能化的关键基础。

### 1.2 问题与挑战

现阶段储层参数计算仍以传统物理模型和经验公式为主，存在三方面局限：

1. **人工依赖程度高**：计算流程需要地质与测井人员反复调参校正，流程繁琐，难以支撑大规模井网快速评价；
2. **场景泛化能力弱**：面对强非均质性、岩性突变等复杂地层，不同区块预测精度波动明显；
3. **数据价值挖掘不足**：测井数据维度丰富，传统方法难以充分挖掘多曲线间非线性关联。

针对上述问题，可通过人工智能方法构建数据驱动的预测模型，减少人工干预，提升复杂地层场景下的预测稳定性，充分挖掘多测井曲线的关联信息，全面提升储层参数计算效率与精度。

### 1.3 算法任务描述

参赛队伍基于官方提供的真实测井曲线数据集搭建模型，对各深度点三类储层参数进行**回归预测**：输入多维测井曲线，输出每个深度点对应的孔隙度（POR）、渗透率（PERM）、含水饱和度（SW）连续数值。

> **本赛题基线为 75 分，最终 B 榜综合得分必须超过该分数线，方能具备晋级决赛、参与奖项评选的资格。**

### 1.4 赛制设置

初赛规则、决赛规则等赛制设置见【赛事中心 - 赛事整体说明】。

## 二、数据集说明

### 2.1 数据集划分

数据集包括 **80 口训练井、10 口测试井**数据，文件统一以 **“井次ID.txt”** 命名。

1. **训练集**：包含全部输入曲线与 POR、PERM、SW 输出曲线，**第一行为曲线名称**，后续为逐行采样数据。
2. **测试集**：与训练井数据格式相同，但**只有输入曲线，无输出曲线**。

## 三、提交规范

队伍全体成员均可通过工作台完成提交，每支队伍设有单日提交次数上限（**5 次/日**），达到上限后当日无法再次提交。提交内容包含**代码文件**和**预测结果**，均为 zip 格式，具体要求如下：

### 3.1 预测结果提交要求

必须严格按照指定 JSON 结构输出预测文件 **`result.json`**，**禁止增删、修改任意字段**，打包为 **`result.zip`** 上传评测，JSON 标准格式如下：

```json
{
  "resultData": [
    {
      "logId": "39dc13c9ca1e4f0eb5f9cb311fe564c3",
      "predictions": [
        {
          "DEPTH": 505.0,
          "POR": 0.1,
          "PERM": 12.35,
          "SW": 0.426
        },
        {
          "DEPTH": 505.1,
          "POR": 0.102,
          "PERM": 13.02,
          "SW": 0.431
        }
      ]
    }
  ]
}
```

> 实测提醒：数据包内自带的 `测试数据返回结果格式.json` 模板比本页示例多出顶层 `modelId`、`modelName`、`version` 字段，且深度字段写作小写 `depth`；请以数据包内模板为准，详见 [附二](#附二datazip-实际内容只读核对)。

### 3.2 代码文件提交要求

必须同步提交完整、可独立运行、结果可复现的代码包 **`submission_code.zip`**。保证在复现时，能够通过命令行指定数据路径和结果输出路径，一次性完成数据读取、预处理、模型加载、推理预测及结果文件生成，而无需人工修改代码、手动写入数据或交互式调试操作。

代码目录结构如下：

```text
submission_code.zip
├── README.md            # 算法说明、运行方式、依赖环境
├── predict.py           # 主预测脚本
├── requirements.txt     # Python 依赖包列表
├── config.yaml          # 可选，模型参数或路径配置
├── src/                 # 可选，算法模块代码
│   ├── model.py
│   ├── feature.py
│   └── utils.py
├── models/              # 可选，训练好的模型文件或权重
│   ├── model.pkl
│   └── scaler.pkl
└── examples/            # 可选，样例输入输出说明
    └── result_example.json
```

**README.md 建议包含内容：**

1. **算法名称**：如基于时间序列特征融合的测井曲线异常检测模型；
2. **方法简介**：简述模型架构、特征工程、训练策略、预测逻辑；
3. **运行环境**：列明 Python 版本、全部依赖包及对应版本；
4. **运行命令**：提供可直接复现预测流程的完整执行指令，如
   `python predict.py --data_dir ./data --output ./result.json`，参数说明如下：
   - a. `--data_dir`：用于指定测试数据目录或文件路径，评测 data 文件夹下目录结构与赛事下发的原始数据完全一致；
   - b. `--output`：用于指定预测结果保存路径。
5. **文件说明**：标注核心脚本、模型权重、特征处理模块用途。

## 四、评分规则

### 4.1 榜单生成机制

比赛平台依据选手提交结果，自动计算 A 榜得分、B 榜得分。

- **A 榜得分**：根据 **5 口测试井**数据计算得出，实时显示，用于模型调优；
- **B 榜得分**：根据**全部 10 口测试井**数据计算得出，赛后统一发布，用于选手晋级、评级。

### 4.2 统一客观评价指标

初赛、决赛采用同一套量化打分标准。

针对测试集中的 $N$ 个深度点，设 $y_i$ 为真实值，$\hat{y}_i$ 为模型预测值，为防止分母为零，引入极小值 $\varepsilon = 10^{-5}$。各项参数的准确率定义如下：

#### ① 孔隙度（POR）准确率 $\mathrm{Acc}_{POR}$

$$
\mathrm{Acc}_{POR} = \frac{1}{N}\sum_{i=1}^{N} \max\left(0,\ 1 - \frac{\left|\hat{y}_i - y_i\right|}{0.08 \times \left(\left|y_i\right| + \varepsilon\right)}\right)
$$

#### ② 渗透率（PERM）准确率 $\mathrm{Acc}_{PERM}$

$$
\mathrm{Acc}_{PERM} = \frac{1}{N}\sum_{i=1}^{N} \max\left(0,\ 1 - \left|\log_{10}\left(\max\left(\frac{\hat{y}_i}{y_i},\ \varepsilon\right)\right)\right|\right)
$$

#### ③ 含水饱和度（SW）准确率 $\mathrm{Acc}_{SW}$

$$
\mathrm{Acc}_{SW} = \frac{1}{N}\sum_{i=1}^{N} \max\left(0,\ 1 - \frac{\left|\hat{y}_i - y_i\right|}{0.05 \times \left(\left|y_i\right| + \varepsilon\right)}\right)
$$

综合百分制总分：

$$
Total\_Score = (0.3 \times \mathrm{Acc}_{POR} + 0.35 \times \mathrm{Acc}_{PERM} + 0.35 \times \mathrm{Acc}_{SW}) \times 100
$$

> 整理者注：POR 相对误差容忍系数为 0.08、SW 为 0.05；PERM 采用对数比值误差。三项权重为 **0.3 / 0.35 / 0.35**（渗透率与含水饱和度权重更高）。

## 五、复现说明

### 5.1 复现目的

复现验证的目的是保证选手提交的预测结果是由提交代码真实运行而来，确保比赛公平公正。

### 5.2 复现流程

1. 初赛结束后，根据各赛题 B 榜排名由高到低，依次选取拟晋级队伍。
2. 下载队伍最终提交的代码包和预测结果文件。
3. 根据队伍提交的 README.md 中的运行环境说明，配置复现环境。
4. 按照 README.md 中提供的可直接复现预测流程的完整执行指令，运行代码生成预测结果。
5. 执行评分脚本验证得分一致性，以比对复现生成的预测结果与选手提交的预测结果。

### 5.3 复现验证标准

1. **代码可独立运行**：无需人工修改代码、手动写入数据或交互式调试操作，即可通过命令行完成完整训练 + 推理流程。
2. **结果一致性**：复现生成的预测结果与选手提交的预测结果一致（允许因浮点精度导致的微小差异），建议选手在代码内部固定随机种子。
3. **运行环境可复现**：README.md 或 requirements.txt 中明确列明 Python 版本、全部依赖包及对应版本。

### 5.4 异常处理

1. **复现失败**：包括代码无法正常运行、复现结果与提交结果不一致两种情况，记录失败原因，取消该队伍的晋级资格，由后续排名队伍依次递补。
2. **发现作弊行为**：如发现代码与预测结果严重不符、存在数据泄露等作弊行为，立即取消比赛资格及所有成绩。

## 附二：`data.zip` 实际内容（只读核对）

本目录下 `data.zip` 已解包核对（只读，未修改文件）：

```text
data/
├── train/                          # 80 个训练井 txt，文件名即井次 ID
├── test/                           # 10 个测试井 txt（仅输入曲线）
├── 参数说明.docx                    # 参数说明文档
└── 测试数据返回结果格式.json          # 提交 JSON 模板
```

共 **92** 个文件（80 + 10 + 2）。

**1. 数据文件格式（实测）**

- 每个 `.txt` 实为逗号分隔文本，**包含两行表头**：第 1 行为曲线名，第 2 行为单位，其后为逐行采样数据。
- 训练井列顺序（17 列）：
  `DEPTH, GR, PE, SP, CAL, AC, DEN, CNL, RXO, RT, DEVI, AZIM, BIT, CASE, POR, PERM, SW`
- 测试井列顺序（14 列，**仅输入曲线**）：
  `DEPTH, GR, PE, SP, CAL, AC, DEN, CNL, RXO, RT, DEVI, AZIM, BIT, CASE`
- **实测列顺序与页面释义表顺序不同**（页面表格是 DEPTH、DEVI、AZIM、GR… 的说明顺序），解析时请以文件表头为准，勿按序号位置硬编码。
- 缺失值以 **`-99999`** 填充（如 CASE 列常为 `-99999`；部分层的 POR/PERM/SW 亦为 `-99999`），需在预处理时按缺失值处理。
- 单位行示例：`m, API, b/e, mV, cm, μs/m, g/cm3, %, ohmm, ohmm, DEG, DEG, none, none`（个别测试井文件的 GR 单位行写作 `mg`，属数据本身差异）。

**2. 提交 JSON 模板（`测试数据返回结果格式.json`）**

数据包内模板**比页面示例多了三个顶层字段**，且深度字段为**小写 `depth`**：

```json
{
  "modelId": "",
  "modelName": "模型名称",
  "version": "1.0",
  "resultData": [
    {
      "logId": "39dc13c9ca1e4f0eb5f9cb311fe564c3",
      "predictions": [
        { "depth": 505.0, "POR": 0.1,   "PERM": 12.35, "SW": 0.426 },
        { "depth": 505.1, "POR": 0.102, "PERM": 13.02, "SW": 0.431 }
      ]
    }
  ]
}
```

> 与页面 3.1 示例的差异汇总：① 多出 `modelId` / `modelName` / `version`；② 深度键名为 `depth`（页面为大写 `DEPTH`）。页面要求“禁止增删、修改任意字段”，建议**以数据包内模板为最终依据**，并优先保证 `resultData[].logId` 与测试文件（井次 ID）一一对应。
